# 记忆 P0：48 episode 基线报告

报告文件：`benchmarks/results/memory-p0-48.json`  
脚本：`benchmarks/benchmark_memory_p0.py`  
状态：确定性 proxy/replay 基线，不是实时 Jev 质量结果。

## 设计

4 个 needle 位置（head/middle/tail/boundary）× 3 种摘要情况（none/date/negation）× 4 种状态（fresh/stale/conflict/distractor），共 48 个 episode。选择器只看到 page summary 和候选控制项，目标页、原文和评分标签在选择结束后才用于评分。`stale` 情况要求 revision guard 拒绝过期读取；`conflict` 要求同时读取当前与历史冲突页。

指标严格分开：

- page hit：目标 page 是否被读入 selected set；
- needle evidence recall：目标原文是否被读取；
- answer correctness：目标证据和冲突证据是否满足该 episode 的检查器；
- guard safe：stale 是否被安全拒绝。

## 结果

本轮实际运行结果（固定 seed=7）：

| 指标 | 结果 |
| --- | ---: |
| episode 数 | 48 |
| page hit rate | 50.0% |
| needle evidence recall | 50.0% |
| answer correctness | 50.0% |
| stale guard safe rate | 100.0% |
| 平均读取字节 | 373.25 B |

分状态看，`fresh` 与 `distractor` 的 needle/answer 均为 100%；`stale` 的读取和答案均为 0%，但全部被安全拒绝；`conflict` 的读取和答案均为 0%。位置和摘要 omission 三个维度均为 50%，说明当前瓶颈不是 needle 在文本中的位置，而是摘要预筛选策略。

## 预期与边界

这是比当前 5-case memory matrix 更系统的基线。结果比“所有情况都能正确恢复”的理想预期差，但符合基线用于暴露问题的预期：摘要-only 在 fresh/distractor 上工作，在 stale 上安全拒绝，在 conflict 上因 TOP-2 前缀被冲突页和 decoy 占用而漏掉当前页。失败原因是选择器只排序摘要和标签，缺少摘要缺口检测、冲突配对和原文回读；不是执行器越权。下一轮按计划加入摘要 gap → raw span fallback，再比较混合检索和实时事件刷新。
