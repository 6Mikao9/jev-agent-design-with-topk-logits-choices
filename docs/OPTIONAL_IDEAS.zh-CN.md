# 补充研究方向与备选路线

作者：匿名作者 · 版本：v0.4-design · 日期：2026-09-23

本文记录六项研究方向的设计取舍：I1 与 I3 已纳入主设计；I2 独立成文；I4、I5、I6 保留为备选路线。编号表示讨论顺序，不代表新颖性或预期收益的排名。这些都是研究假设，未完成全面文献查重，也没有实验结果。

主文档已经包含用户提出的多层记忆、辅助小模型与微调、Top-k 参数构造、扩散提案、候选刷新及自然交互。本清单在这些方向上提出更具体的研究问题。

## I1. 按决策影响管理多层记忆

已纳入[主设计](DESIGN.zh-CN.md)第 3.4、8.6 节。以下保留研究动机与评估思路。

### 想法

在多层记忆之上，增加“是否可能改变当前决策”的保留和召回标准。相似度高的内容未必有用；一句很短的限制可能直接排除大半动作。

例如，“用户本次只允许使用两张 GPU”应优先进入当前上下文；多段主题相似、却不影响当前参数的历史日志可以留在冷层。

### 可实现机制

1. 每条记忆关联它涉及的实体、参数、约束、候选分支和证据。
2. 从当前决策所依赖的字段向外查找相关记忆。
3. 用规则或 Jev 判断该记录是否影响候选可行性、偏好或参数来源。
4. 在固定预算下，优先取回影响关键约束的记录。
5. 离线通过移除或替换单条记忆，测量选择和最终成功率是否变化，用于改进召回策略。

移除后动作发生变化，并不自动说明变化有益；还需要执行结果或任务标签判断方向。

### 研究价值与验证

关键比较是同等 token 预算下，按语义相似度、时间、固定冷热策略，以及按决策影响召回的差别。重点观察长任务、用户改口和环境变化后的恢复率，以及遗漏关键约束的比例。

多层记忆已有 [MemGPT](https://arxiv.org/abs/2310.08560) 等工作。潜在增量应具体落到候选和参数依赖如何改变记忆调度，而不能仅称“设计了五层记忆”。

## I2. 检测候选集合缺失

已单独整理为[候选覆盖诊断与恢复](CANDIDATE_COVERAGE.zh-CN.md)。该问题与 Top-k 回退相关，但不能把添加一个 fallback 选项等同于可靠识别了候选缺失。

## I3. 依据依赖局部重规划

已纳入[主设计](DESIGN.zh-CN.md)第 3.4、4.5、9.2 节。以下保留研究动机与评估思路。

### 想法

为候选、参数和记忆记录它们依赖的事实。任务条件变化时，只重做受影响的部分，并从冷层找回现在重新适用的分支。

例如，原任务是“明晚在 A 节点运行”，随后改成“今晚、最多两张卡”。时间和配额相关节点失效；已读取的任务配置可能仍有效；此前因约束被淘汰的 B 节点方案可以重新参与选择。

### 可实现机制

为每个记录维护任务版本、工具版本、来源实体和读取过的事实。状态变更产生失效集合，再沿显式依赖关系传播。复用前检查当前前置条件；冷分支重新进入候选后，由 Jev 基于当前状态评分。

未执行分支的预期效果保留为假设。该机制不提供外部工具动作自动回滚；有副作用的动作仍需遵循工具原有的恢复方式。

### 研究价值与验证

与完全重新生成、只复用文本缓存比较，测试用户改口、资源变化及 schema 更新场景中的恢复延迟、复用比例和陈旧参数误用率。依赖漏记可能让系统错误复用，因此还要衡量依赖记录是否完整及其维护开销。

增量计算与缓存失效是已有思想。[CaSKG](https://arxiv.org/abs/2608.25500) 也研究了反事实探测与受状态约束的技能检索。这里值得细化的范围是在线候选、参数和记忆之间的依赖失效；需要进一步检索局部规划与 agent 缓存文献。

## I4. 自适应决定参数构造粒度

状态：备选。主设计已经采用粗粒度提案优先、显式 `FALLBACK_TOPK` 的路径；本项研究进一步推广为基于成本或学习的粒度调度。

### 想法

原方案已经包含完整调用、字段、片段与 token 四种粒度。可以进一步让运行时根据字段结构、候选质量、延迟预算和历史成功率选择粒度。

固定枚举直接选择；原文中的路径直接复制；开放说明生成完整字段；较短且结构敏感的表达式探索片段提案；逐 token 仅在值得支付串行成本的任务中尝试。

### 可实现机制

把工具参数组织成依赖图，先识别确定值、可复制值和需要生成的字段。为每种粒度估计调用轮数、候选覆盖和校验通过率。初期用明确规则，积累数据后再考虑学习选择策略。

### 研究价值与验证

直接比较整步转给 LLM、完整调用生成后重排、局部字段补全和自适应粒度。要包含未见工具和跨字段约束任务。如果 token 模式长期更慢且不改善正确率，应如实保留这一结果。

[Pydantic AI 的 Jev 集成](https://pydantic.dev/docs/ai/models/typesafe/) 已有工具处理与 LLM 回退，构成重要基线。候选增量是局部补全和粒度调度的具体机制，不能把“兼容现有 agent 工具”本身当成首次贡献。

## I5. 统一分配生成、检索与交互预算

状态：备选。主设计保留基本预算与退出条件，尚未采用学习得到的统一资源控制器。

### 想法

让运行时决定下一步资源该用于哪种行为：执行已有动作、再生成一组候选、查冷记忆、重新观察环境、问用户，或交给能力更强的模型。

这可以把记忆、候选与自然交互连接起来，避免每个模块独立多调用一次模型。

### 可实现机制

把这些行为定义为控制动作，依据当前约束缺口、候选覆盖风险、信息新鲜度和剩余预算估计收益。目标可表达为预期任务收益减去调用费、等待时间和交互成本，但各项估计需要从实际任务数据获得。

不能把 Jev 的概率熵直接当作任务收益。即使模型仍不确定，执行一个低成本观察工具也可能比继续问模型更有效。

### 研究价值与验证

与固定候选数量、固定阈值和固定回退规则比较每个成功任务成本、尾延迟、用户被打断次数和任务成功率。若控制器频繁选择继续搜索而无法停止，就没有达到目标。

[Structured Uncertainty guided Clarification for LLM Agents](https://aclanthology.org/2026.findings-acl.2028/) 已利用工具参数不确定性与信息价值组织澄清。需要研究的具体增量是能否同时调度生成、记忆、观察与交互，并改善整个系统的资源分配。

## I6. 用执行反馈训练候选生成器

状态：备选。原始的辅助模型微调方向继续保留；本项专门研究候选集合质量与执行反馈的训练目标。

### 想法

在原有辅助微调方向上，把训练目标从“生成一个像样答案”改为“生成少量但覆盖关键可能性、可执行的一组候选”。

候选集里应该有有效差异。例如两个不同的查询策略可能有价值，五种近义改写未必有价值。

### 可实现机制

记录每组候选、校验结果、Jev 选择、执行反馈和最终任务结果。离线训练可优化正确候选覆盖、无效候选比例和候选冗余，同时控制生成长度。

未执行候选通常没有真实结果，不能直接标为失败。可在可控环境里增加离线评估，或明确使用仅对已执行动作成立的反馈。

### 研究价值与验证

固定候选数与生成预算，比较微调前后的候选覆盖率、实际任务成功率、语义多样性及未见工具上的迁移。特别检查生成器是否只学会获得 Jev 高分，实际结果却没有改善。

执行反馈训练、蒸馏和偏好优化已有广泛研究。本轮检索不足以界定新颖性，建议在基本系统产生可信数据之后再收敛这一方向。

## 当前设计取舍

当前以 **I1 + I3** 作为主设计中的共享状态机制：分层记忆和局部恢复使用同一组依赖引用。Top-k 显式回退也已纳入主流程。

**I2** 单独展开失败模式和诊断方法；**I4、I5、I6** 作为备选路线保留在本文。后续是否进入实现，依据原型瓶颈、实验收益和可用数据决定。

最终应根据原型中真实暴露的瓶颈收敛贡献。增加模块数量不会自动增加论文新颖性；每项都需要一个可检验的问题和能够否定收益假设的对照。
