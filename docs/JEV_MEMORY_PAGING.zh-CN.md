# 面向 Jev 的分层页表记忆（设计草案）

这是一项待验证的系统设计，不声称提出了全新的记忆检索算法。它把已有的分层检索、摘要记忆、LRU 和 RAG 组合成适合 Jev 候选选择的接口：Jev 不直接面对整段历史，而是先选择页表条目，再从少量条目中决定精确读取哪些记忆。

## 目标

- 把长历史切成有边界的记忆页，每页由内嵌小模型生成短摘要，摘要作为页表条目的一部分。
- 让 Jev 输出有限候选分布，而不是一次回答“读哪些记忆”的开放文本多选题。
- 在不超过固定页数、字节数和延迟预算的情况下读取可复核的原文。
- 记忆陈旧、上下文冲突或候选不足时，能够请求重检索、澄清或停止。

## 两阶段读取

```text
当前上下文 + 任务状态
        │
        ├─ 小模型：提取查询/过滤条件（可选）
        │
        ├─ 粗检索：BM25/向量/RAG 预筛 + Jev
        │       输出 page_id 的有限概率分布
        │       取 top-M，M 有上限
        │
        ├─ 精检索：上下文 + M 个页表摘要 + 控制项
        │       Jev 选择 top-K page_id 或 NONE/CLARIFY/STOP
        │       K ≤ M 且有硬上限
        │
        └─ 读取 K 页原文/结构化字段，校验版本后交给 agent
```

第一阶段只呈现页表摘要和稳定的短 ID，例如 `mem_017`，不把整页原文塞进 Jev。这里要区分责任：BM25/向量预筛只负责从全索引召回不超过 `M_pre` 的候选，Jev 看到这些候选后负责给出页 ID 分布和 `NONE/CLARIFY/STOP` 控制；不能把预筛分数直接当成 Jev 选择。第二阶段只呈现第一阶段留下的候选，允许 Jev 选择多个条目；`NONE` 表示当前记忆不足，`CLARIFY` 表示查询本身有歧义，`STOP` 表示不要继续读取。任何未被选中的页都不能因为概率较低而自动注入上下文。

推荐初始预算：`M=16`、`K=4`、单页原文上限 8 KiB、总读取上限 32 KiB；这些数值只是起点，应按任务和显存/延迟测量调节。若 Jev 给出的概率质量低、页表摘要互相冲突或依赖版本已变化，则降级到 RAG 重新召回或人工复核。

## 页表条目

每个条目至少包含：

- `page_id`、父级/子级 ID、创建时间和最近访问时间；
- 小模型摘要、主题/实体标签、来源 trace ID 和内容哈希；
- 数据依赖版本、敏感级别、可读字段范围和失效状态；
- 可选的向量/BM25 索引键，但索引分数只能用于预筛，不能代替 Jev 的最终选择。

约 200 个一级目录是可行的起始规模。超过这个规模时可以增加月份/任务/主题等二级目录，或让老页面合并成更高层摘要页。层级只影响候选召回，不改变最终原文读取的版本校验。

## 老化、LRU 与 RAG 组合

- 热页保留较短路径和较新摘要；冷页提高层级、合并为父页，并保留可追溯的子页 ID。
- LRU 只能作为召回排序或缓存淘汰信号，不能绕过依赖版本、权限和 Jev 的选择。
- RAG/向量检索负责扩大候选召回，Jev 负责在有限候选中选择、拒绝或请求澄清；两者的分数和选择理由都写入 trace。
- 摘要更新后递增 `memory_revision`，旧候选在执行前失效，避免上下文改变后仍读取过期页。
- 任何摘要都不应包含密钥、未授权的跨工作空间内容或不能回溯的结论；原文读取由工具层再次执行路径和权限检查。

## 与现有原型的衔接

现有 `MemoryBank` 已有依赖版本和失效概念。可以新增一个 `PagedMemoryIndex` 适配层，把 `MemoryRecord` 映射成页表条目，再把两阶段结果转为当前 Agent 的 `decision_dependencies` 和 `impact_tags`。早期实现不需要引入新的向量数据库：先用确定性的页表、BM25/关键词预筛和 fake Jev，固定回放后再接 embedding/RAG。

推荐接口形状：

```python
coarse = index.select_pages(context, limit=16)
fine = jev.choose_pages(context, summaries=coarse, limit=4)
pages = index.read_selected(fine.page_ids, max_bytes=32_000)
```

`select_pages`、`choose_pages` 和 `read_selected` 都应记录候选集合、页版本、被拒绝的 ID、预算和耗时；没有 `fine` 的明确选择时不读取原文。

## 评测计划

先构造带有时间冲突、同名实体、长噪声 trace 和已失效依赖的本地数据集，比较：

1. 全量历史、单阶段 RAG、固定 top-K RAG、两阶段 Jev 页表；
2. 记忆召回 `recall@M`、最终读取 `precision@K`、任务成功率、错误副作用和澄清率；
3. Jev 选择次数、小模型摘要/预筛耗时、读取字节数、缓存命中率和 stale 命中率；
4. M/K/页大小、层级深度和 LRU 策略变化下的质量—延迟曲线。

评测必须固定页内容、摘要模型、候选 ID、随机种子和版本。除了 `recall@M` 和 `precision@K`，还要记录“相关页未进入粗选池”的漏失率、关键事实覆盖率、长尾旧事实召回率，以及父页合并前后的事实保真度。增加两个消融基线：只有分层检索但不让 Jev 精选、以及单阶段 RAG；这样可以把目录层级收益和 Jev 选择收益分开。语言模型裁判只能作为补充，最终正确性应优先由结构化状态、依赖版本和任务里程碑判定。

概率质量不能只看单次最大值：应测选择稳定性、校准误差和不同候选顺序下的变化，并为 `NONE/CLARIFY/STOP` 设定可回放的阈值和错误代价。LRU 只做缓存淘汰或排序时，要专门测低频但关键的旧事实；父页摘要合并后，原始子页仍应可回溯。延迟和成本要拆成粗检索、Jev 两阶段推理、小模型摘要、原文读取四项，避免把目录命中误认为端到端收益。

## 风险与边界

- Jev 的概率分布不是可靠的相关性分数；必须使用硬上限、`NONE/CLARIFY/STOP` 和执行前版本校验。
- 页表摘要可能遗漏矛盾信息；冲突字段应保留原文定位，不能只保留小模型的单句总结。
- 多级页表会引入额外延迟和错误传播，必须测量是否真的优于简单 RAG。
- 该设计不提供安全隔离。页内容、索引和摘要仍需放在受控工作空间中，密钥不应进入摘要或 trace。
